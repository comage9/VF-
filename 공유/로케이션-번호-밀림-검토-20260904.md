## 1. 핵심 결론 (요약)

1. **"번호가 따라간다"는 칸 이동 경로에서만 발생**: 제품만 이동(드래그/수기편집)하면 번호는 원칸에 불변(원칙 준수). 그러나 **칸/셀 이동**(moveSlotTo·moveCellTo·방향키·좌표이동)은 zone 객체째 옮기므로 locNo가 좌표를 따라감 — 사용자가 본 현상의 정체.
2. **77~151번(75개)이 화면에 전부 미표시**: layout 복원 시 L5~L7 zone의 locNo/locNos가 저장본에 없어 영구 소실 + d28b777의 L7 번호 강제 삭제.
3. **짝수 라인(L2·L4·L6) 번호가 칸 우측 18px 고정 배치** = "우측 밀림" 인식의 직접 원인 (실측 +36px). 최상단 로우는 같은 번호가 2곳에 중복 렌더됨.
4. **데이터 결손**: 37번(L1-1) 결번, L3-16/L4-16 유령값(70/69) 이중 정의, A-L1-10·L3-19·L4-18 존 부재(→20·76·73 표시 불가), localStorage 스테일 번호(L4-19=81 등) 잔존.
5. **코드 맵 자체는 39~76 무중복·무결번, 77~151 합산 완비** — 문제는 "맵 ≠ 화면 zone 보유값" 불일치가 핵심.
