## 1. 발견된 결함 (시뮬레이션 근거)

`computeLocNosAll`의 manual 처리:
```js
const manual = manualLocNos[c.zoneId];
if (manual != null && manual > 0) cursor = manual;   // ← 하한 검사 없음
```
**manual 값이 그 칸의 현재 자동 시작 번호(진행 중 cursor)보다 작으면, 앞 칸들이 이미 쓴 번호와 중복**된다.

시뮬레이션:
| 케이스 | 결과 |
|---|---|
| manual=5, 현재 cursor=4 (뒤로 미는 경우) | ✅ 정상 (5부터, 앞번호 불변) |
| manual=2, 앞 칸이 이미 2,3 사용 중 | ❌ **2,3 중복** |

사용자 의도: "입력한 값에 따라 **뒷번호가 자동 증가**" = manual은 그 칸의 시작점. 앞번호보다 작은 값을 넣으면 앞과 충돌하므로 **허용하면 안 된다.**

## 2. 수정 요구

1. **manual 입력 검증/처리**:
   - (권장) 입력 UI 단계에서 **"이 칸의 자동 시작 번호보다 작은 값은 거부** (안내 메시지)" 하거나
   - 또는 manual 값이 cursor(앞번호 끝+1)보다 작으면 **cursor를 manual로 되돌리는 대신 무시**(자동 유지) + 사용자에게 "앞 번호와 겹침 — 자동 번호를 유지합니다" 표시.
2. manual 값이 **앞번호와 안 겹치는 최소값**을 계산해, 입력 시 그 값 이상만 받도록 하드 가드 추가:
   - `minAllowed = (직전 칸까지 쓴 마지막 번호) + 1`
   - UI에서 minAllowed 미만 입력 → 즉시 안내 & 자동 모드 유지(또는 minAllowed로 보정).
3. 혹시 "앞번호를 의도적으로 당기고 싶다"(전체 재정렬)는 요구면 별도 문의 — 기본은 앞번호 불변.

## 3. 추가 확인 요청 (구현 후 자체 검증)

- 수동 입력이 **A동 첫 칸(rank 최소)에 1보다 큰 값**이어도 정상 (뒤만 밀림)
- 빈 칸에 manual → 그 칸 1개만 그 값, 뒤는 +1
- 수동 값 삭제 → 자동 복귀 시 중복 0
- 서버 저장/복원 후 manual 유지
- tsc·빌드, 커밋
