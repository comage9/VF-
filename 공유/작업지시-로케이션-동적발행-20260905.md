# 작업지시서 — 로케이션 번호 동적 자동 발행 (opencode 실행)

> **지시자**: Hermes (2026-09-05) · **실행자**: opencode · **검증자**: Hermes (재실측)
> **성격**: 좌표·칸 고정 + 제품 유동 → 로케이션 번호를 **배치 데이터 기반으로 자동 계산**하도록 전환.
> 사용자 확정 규칙 (2026-09-04/05) — 이 지시서가 최우선 기준.

---

## 1. 확정 규칙 (사용자 원문 요지)

1. **좌표(X,Y)·칸(그리드)은 완전 고정.**
2. **제품 배치는 유동적** — 오늘 (4,14)에 1개, 내일 2개가 들어갈 수 있음. 제품이 확정 고정 배정된 게 아님.
3. **로케이션 번호는 좌표 순서대로 "각 칸의 품목 수"만큼 연속 발행**:
   - 칸마다 **기본 1개** 번호를 가진다 (제품 없어도 그 자리 번호 1개 — 예: (9,3) 빈 칸도 자기 번호).
   - 그 칸에 제품이 N개 있으면 그 칸이 **N개 연속 번호**를 쓴다 (최소 1).
   - 예: (4,14) 제품 1개=번호 1개 → 다음 칸 (4,15) 제품 없음=다음 번호 1개 → (4,16) 제품 2개=그다음 연속 2개.
   - **칸 안의 제품 순서**: 아래쪽/앞쪽 제품 = 낮은 번호 (기존 유지).
4. **변동 시 자동 시프트**: 어떤 칸에 제품이 추가되어 그 칸이 쓰는 번호 수가 늘면, **그 뒤(높은 쪽) 모든 좌표의 번호가 순차적으로 밀린다** (재계산이라 자연 해결).
5. **동별 번호 구간**: 예 — A동 1~200, B동 201~400(경계는 아래 §3). 각 동 구간 내에서만 발행·밀림.
6. 로케이션 번호는 **저장값이 아니라 배치(data)에서 파생되는 계산값** — 저장할 필요 없이 항상 최신 배치 기준으로 계산.

## 2. 현재 구조 → 무엇을 바꾸나

**현재 (정적 맵)**: `A_LOCNO_MAP`/`A_LOCNOS_MAP` 상수(하드코딩 1~151) → `A_COORD_NOS`(좌표→번호 정적 Map) → 화면 오버레이가 이 정적 맵을 좌표에 렌더. **제품 수와 무관하게 고정된 번호**가 붙음 = 사용자 규칙과 불일치 (예: 품목 1개 칸에 번호 2개, 품목 2개 칸에 1개 등 32곳 불일치 확인됨).

**목표 (동적 계산)**:
- 좌표 순서(카논)로 모든 칸을 순회하며, **각 칸의 실제 제품 수 = data[zoneId]의 콤마 개수**에 따라 번호를 발행한다.
- 빈 칸(존은 있으나 data 없음/빈 값)도 1개 번호. data에 아예 없는 좌표는? **빈 칸으로 취급해 1개 번호 부여(자리)** — 단, 실제 그리드에 존재하는 좌표만 (buildGridCoordSystem 좌표 집합 기준).
- 생성된 "좌표→번호 배열" 맵을 화면 오버레이·검색·엑셀·인쇄·미니맵·모바일이 공용 사용 (현재 coordNosByZone/dongLocNos가 정적 A_COORD_NOS를 읽는 지점을 이 계산 결과로 교체).
- 정적 맵(A_LOCNO_MAP/A_LOCNOS_MAP/A_COORD_NOS)은 **삭제 또는 유지하되 사용 중단**. 데이터 존재로는 최신 계산 결과가 우선.

## 3. 좌표 순서(카논)와 동별 구간

- **A동 순서(사용자 확정)**: ① X9/X7 열쌍 **위(Y21)에서 아래로** 지그재그 → ② X6/X4 열쌍 **아래(Y3)에서 위로** 지그재그 → ③ X3/X1 열쌍 **아래에서 위로** 지그재그. (L7 하단 가로 칸과 통로 X2/X5/X8 처리 — L7은 기존 정의 좌표 (n,1); 통로 열은 번호 발행 제외인지 실제 grid 칸 여부로 결정. **코드의 buildGridCoordSystem·A_LINES·A_COORD_NOS 주석을 읽고 실제 좌표 집합·순서를 확정**할 것)
- 각 열(라인) 내 세로는 38px 행 주기, X열 left 매핑은 `buildGridCoordSystem`의 colReps 기준.
- **동별 구간**: A동 = 1부터 시작. B/C/D/E동은 **앞 동이 쓴 마지막 번호 + 1**부터 시작해 각 동의 좌표칸 수(+여유)만큼. 정확한 구간 상한은 각 동 실제 좌표 칸 수를 세어 결정하고 **지시서 보고에 명시** (사용자 예시는 A동 1~200, B동 200~400 식).
- **동 순서**: A → B → C → D → E (또는 화면 탭 순서) — 코드의 동 정의 확인 후 결정.

## 4. 절대 금지 (회귀 방지)

- **제품 배치 data는 절대 변경 금지.** 좌표·layout 존 위치도 변경 금지 (직전 커밋 d39442c에서 표준화 완료).
- **다른 동의 data·layout 무단 변경 금지** (B동 이유정리함 배치 등 기존 작업 보존).
- 로케이션 "표시 위치/스타일"(오버레이 렌더) 로직은 유지 — 값 소스만 교체.
- 사용자 확정 앵커(2031=(4,14), 516=(4,16), 2034=(4,21) 등)와 모순되는 결과가 나오면 **수동 예외 처리보다 규칙을 재확인**하고, 보고에 포함.

## 5. 작업 범위 (권장 순서)

1. **공통 계산 함수 구현**: 예) `computeDongLocNos(data, layoutZones, dong)` — 좌표 순서 순회하며 품목 수만큼 번호 발행. 각 동에 대해 위 규칙.
2. 화면 표시(오버레이/coordNosByZone/dongLocNos), 검색, 엑셀 export, 인쇄, 미니맵, 모바일이 이 계산 결과를 쓰도록 교체.
3. 사용하지 않게 된 정적 맵/잔재 정리(옵션, 안전하게).
4. 제품 추가/제거/이동 핸들러는 data만 바꾸면 번호는 파생 재계산되므로 **별도 시프트 로직 불필요** — 확인만.
5. 서버 스냅샷에 **data·layout 그대로 최신 저장**(번호는 저장 안 함 — 파생값).
6. 검증: tsc 신규 오류 0, 빌드 통과, 화면 실측으로 아래 기준 확인.

## 6. 검증 기준 (완료 전 반드시)

화면(A동) 실측:
1. 각 칸의 amber 번호 개수 = 그 칸 제품 수 (빈 칸 = 1개). 예: 품목 1개 칸=번호 1개, 품목 3개 칸(예: (4,19) 213,233,251)=연속 3개.
2. 좌표 순서상 번호가 **1부터 연속·중복 없음** (각 동 구간 내).
3. 기존 앵커 유지: (4,14)=2031에 번호 1개(61 아님 — 새 규칙이면 값이 달라질 수 있음), (4,16)=516 등이 **그 좌표의 발행 순서와 일치**하는 번호를 가짐. (정적 61/65 대신 재계산된 연속 번호가 붙어야 정상)
4. 한 칸에 제품 1개 추가(임시) → 그 칸 번호 2개 + 이후 밀림 → 원복.
5. 스크린샷 + 변경 요약 + 커밋 (메시지에 실측 검증 명시).
6. 참고: 표시 "61" 같은 기존 정적 번호 기대는 폐기 — **1부터 재계산된 번호**가 정답.
