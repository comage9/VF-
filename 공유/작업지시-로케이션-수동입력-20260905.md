# 작업지시서 — 로케이션 번호 수동 입력 + 자동 재발행 (A동, opencode 실행)

> **지시자**: Hermes (2026-09-05) · **실행자**: opencode · **검증자**: Hermes (재실측)
> **적용 범위**: A동 먼저 (B~E는 나중에 확장 — 코드는 동 공통 구조로)
> 사용자 확정 (2026-09-05): **첫 번호만 입력하면 품목 수만큼 자동 +1 연속 배정**

---

## 1. 목표

현재 로케이션 번호는 `computeLocNosAll`(product-display.tsx:769)이 **배치 data에서 순수 파생 계산**(1부터, 좌표 순서, 빈칸=1, 다품목=품목 수)한다. 여기에 **사용자가 특정 칸의 로케이션 번호를 직접 지정**하면, **그 칸부터 이후(뒤) 번호가 자동으로 밀려 재계산**되는 수동 입력 기능을 추가한다.

## 2. 동작 규칙 (사용자 확정)

- A동 칸 클릭 시 인라인 편집 — 지금은 "제품 번호"만 입력 가능. **로케이션 번호도 직접 입력**할 수 있게.
- 사용자가 어떤 칸에 로케이션 **첫 번호 N**을 입력하면:
  - 그 칸은 **N부터 시작해 (품목 수)만큼 연속 번호**를 받는다. 예: 3품목 칸에 70 입력 → 70,71,72.
  - 빈 칸이면 N 1개.
  - **그 칸 이후(좌표 순서상 더 높은 rank)의 모든 칸 번호는 자동으로 +K 밀려** (K = N이 그 칸의 기존 시작번호보다 커진 만큼) 전체가 다시 1부터 연속이 되도록 재계산.
  - 그 칸 이전(낮은 rank) 번호는 그대로.
- 즉 "수동 고정 지점(시작 번호 N)" 이후는 자동 연속 재발행.

### 예시 (사용자 예시)
- (4,17) 3품목 칸이 원래 74,75,76이었는데 70을 입력 → 그 칸은 70,71,72. 이후 칸들은 기존보다 4씩 앞당겨져 73부터 연속.
- (9,3) 빈칸에 50 입력 → 그 칸 50. 이후는 51부터.

## 4. 구현 방안 (권장)

**수동 번호를 별도 맵으로 저장** (기존 자동 파생은 유지, 얇은 오버레이):
1. **상태**: `manualLocNos: Record<zoneId, number>` (좌표(칸)당 시작 번호 1개만 저장) — A동 전용. localStorage(스냅샷 payload의 기존 `locExceptions` 같은 필드 옆에) + 서버 저장.
2. **계산 수정**: `computeLocNosAll` — 각 칸 순회 시:
   - 칸이 `manualLocNos`에 있으면 → 그 칸의 count 만큼 **manual 값부터** 발행 (cursor를 manual 값으로 세팅)
   - 없으면 기존처럼 cursor 연속 발행
   - cursor는 발행 후 항상 `마지막 부여 번호+1`로 진행 → **자연스럽게 뒤쪽이 밀림**.
3. **UI**: 인라인 편집 다이얼로그/팝오버에 **"로케이션" 입력 필드** 추가 (제품 번호 옆). 값 있으면 manualLocNos 저장/갱신, 비우면 자동 모드 복귀(manual 제거).
4. **표시**: 오버레이는 기존처럼 byZone/byCoord의 계산 결과 표시 — manual 반영된 값이 자연 표시.
5. **제품 추가/이동**: 기존 핸들러는 data만 바꾸므로 계산이 자동 반영. manualLocNos는 좌표(칸) 귀속 유지.
6. **B~E 확장 대비**: manualLocNos를 동 구분 없이 zoneId 키로 저장하되, UI 입력은 **A동에서만** 활성화(다른 동은 추후). 코드는 동 무관 구조.

## 6. 검증 (완료 전 필수)

화면(A동) 실측:
1. 수동 입력 전: 현재와 동일 (1~ 연속, 다품목 수만큼) — 회귀 없음.
2. 어떤 칸에 로케이션 N 입력 → 그 칸이 N부터 품목수만큼, 이후 칸들이 N+품목수부터 연속(중복·누락 0).
3. 입력한 칸보다 앞 칸 번호는 불변.
4. 로케이션 입력 지우기 → 자동 모드 복귀(원래 번호로).
5. 빈 칸에 수동 입력도 동작.
6. 서버 스냅샷 저장 + 새로고침 후에도 수동 값 유지.
7. tsc 신규 오류 0, 빌드 통과, 스크린샷 + 커밋.
