> 목적: 여러 에이전트가 같은 코드베이스를 동시에 작업하면서 생기는 **충돌·지식 분열·무단 변경** 방지. (Idea Foundry 영상의 "사람 승인 게이트 + 작업 가시화" 원칙을 적용)

---

## 1. 작업 시작 전 — 반드시

1. **`작업현황.md` 읽기** — 누가 어떤 작업을 진행 중인지 확인.
2. **같은 파일을 다른 에이전트가 수정 중이면** 해당 작업과 충돌하는 변경을 시작하지 말 것. 필요하면 `작업현황.md`에 "○○ 진행 예정"을 먼저 적고 사용자에게 조율 요청.

## 2. 승인 게이트 (대형 변경)

다음 유형의 작업은 **코드 수정 전에** `공유/작업계획-<주제>-<YYYYMMDD>.md` 계획서를 작성하고 **사용자(주현) 승인**을 받은 뒤 진행한다:

- 소스 코드 구조 변경 / 함수·컴포넌트 리팩터링
- 데이터 모델·DB 변경, 마이그레이션
- 좌표 체계 등 **도메인 규칙**에 영향 주는 수정
- 여러 파일에 걸친 기능 구현

**예외 (승인 불필요)**: 사용자가 대화에서 직접 지시한 작업 / 버그의 즉시 복구(급한 롤백) / 문서·분석 작성. 단 진행 후 `작업현황.md`에 결과를 남긴다.

계획서 최소 내용: 대상 파일 · 변경 요지 · 영향 범위 · 검증 방법 · (참조 문서가 있으면 링크).

## 3. 작업 중 — 현황 기록

- 작업 시작: `작업현황.md`에 행 추가 (작업 / 담당 / 시작 / 상태=진행중 / 대상 파일)
- 작업 완료: 상태=완료 + 결과 요약(변경 파일, 검증 결과) 1~2줄
- 산출 문서(분석·보고)는 `공유/`에 저장, 파일명: `<주제>-<성격>-<YYYYMMDD>.md`

## 4. 원본/소스 수정 원칙

- 스킬·스크립트·문서의 **원본은 한 곳만** 유지 (복사본 두지 않기 — 드리프트 방지)
- 수정 전 현재 diff 백업 권장: `git diff > 공유/백업-<파일명>-<ts>.diff`
- 이 프로젝트 파일은 CRLF — `git diff --ignore-cr-at-eol` 사용
