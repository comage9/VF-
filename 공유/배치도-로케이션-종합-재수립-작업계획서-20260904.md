## 3. 채택 전략 3가지 (Hermes 제안 — 전부 채택)

### 전략 1 — Playwright 화면 실측 루프 (검증 방식 변경)
- Playwright로 localhost:5174를 열어 전체/단독 전환·특정 좌표·스크린샷을 실측
- **수정 → 실측 → 스크린샷 증거 확보 → 커밋** 순서 강제. 화면 증거 없는 커밋 금지
- 담당: Hermes (환경 세팅·실측 스크립트), OpenClaw (수정)

### 전략 2 — 렌더 1개 통일 (구조 변경)
- "좌표 기준 오버레이" 렌더 함수 **1벌**만 유지하고 5개 경로(단독 그리드·총괄 미니맵·로케이션 리스트·인쇄·엑셀)가 전부 같은 함수를 호출
- 좌표↔번호 기준표(A_COORD_NOS, 카논 반영)가 유일한 데이터 소스

### 전략 3 — 기준표 1장 SSOT (데이터 정리)
- A_COORD_NOS(카논 반영) = 유일한 번호 원본
- 존(zone)의 locNo/locNos 필드·storedLocNos·스테일 값은 **표시 경로에서 완전 제거**

## 4. 실행 단계 (재수립)

### P0-1. 카논 SSOT 재생성 (③구간 반전 수정)
- A_COORD_NOS를 **카논대로 재생성**: ①②구간(1~76) 유지, **③구간(77~151) 상하 반전 수정** — L5-1=77, L6-1=78, L6-2=79, L5-2=80 … X3/X1 쌍 Y3에서 위로 뱀
- L7(하단 8칸×2품목 = 136~151)·신규 칸 번호: **현장 확인 보류** — 기준표에서 제외하고 별도 확정
- 산출: 수정된 기준표 + 전 좌표 시뮬레이션 증명 (기존 방식 재사용)

### P0-2. 렌더 1개 통일 (5경로 → 1함수)
- 신규 공용 함수 `locLabelOf(zoneId): { nos: number[]; coord: string } | null` 1벌
- 5개 경로(ZoneCell 칩·MiniZoneCell 칩·locNoOf 패널·엑셀 no 열·인쇄)가 전부 이 함수 호출로 교체
- 존 저장값(zone.locNo/locNos)·storedLocNos 참조 **전면 제거**

### P0-3. Playwright 화면 실측 루프 구축 (Hermes 협업)
- Hermes가 Playwright 환경 세팅 → OpenClaw 수정 → Hermes 실측 → 스크린샷 증거 → 커밋
- 첫 실측 시나리오: 전체/단독 전환, (4,14)=61, (4,16)=65, (9,3)=37 빈 칸, (9,12)=20

### P1. 렌더 정합 보강
- 다품목 구획 번호 규칙 정합 (locNos.length===1 반복 표시 제거, 세로 위/아래 반전 정합)
- 미니맵 z.locNo 폴백 제거 (스테일 누출 차단)
- 칩 사이드 규칙: 가까운 통로 방향 (col % 3 기준) 유지

### P2. 잔재 제거 (데이터 보정)
- storedLocNos 함수·존 locNo/locNos 표시 폴백·mirrorLocNos/syncLocNosAfterDataChange **제거** (번호는 좌표 귀속이므로 불필요)
- placement_location_sync 가드 유지 (이미 적용)
- A_LOCNO_MAP/A_LOCNOS_MAP: L1-1=37 유지, 유령값(70/69) 정리

### P3. 화면 실측 최종 검수 (사용자)
- 전체/단독 전환, (4,14)=61, 빈 칸 37, 배율(120/220/130/220) 확인 → 승인 시 완료
