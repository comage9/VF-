## 2. 문제 ① — A동 좌표 범위(X≤9/Y≤21)와 통로 좌표

### 요구사항 (현장)
A동에 한해 X축 9열까지, Y축 21행까지 존재하며, **통로(사이 간격)에도 좌표 번호가 매겨져야 함**.

### 코드의 설계 의도 (존재함)
`product-display.tsx` 1899~1900, 1903, 1915행 주석이 정확히 이 요구사항을 명시:
```
X: 1=L6, 2=통로, 3=L5, 4=L4, 5=통로, 6=L3, 7=L2, 8=통로, 9=L1
Y: 1=L7, 2=통로, 3=L6, 4=L5, 5=L4, 6=L3, 7=L2, 8=L1, 9~21=확장
```

### 구현 결함 (왜 미달인가)
| 결함 | 위치 | 설명 |
|---|---|---|
| **통로 열 좌표 생성 불가** | `getColCenterX` 1902~1911 (lineMap 1904에 2·5·8 없음) | 통로 열(X=2,5,8)은 `lineMap[col]`이 없어 **0 반환** → 열 라벨 루프(1949) `continue`, coordOf의 최근접 열 후보에서도 제외(1987~1995) → 통로에 인접한 칸·A-X1/X2 특수칸이 **옆 랙 열(1·3·4·6·7·9)로 스냅** |
| 통로 시각 표시도 불발 | 1966~1972 | 회색 "통로" 텍스트도 `cx===0`이면 생략 → 화면에 통로 표식 없음 |
| **행 3~8 겹침** | `getRowCenterY` 1932~1938 | L6~L1이 전부 **세로 컬럼**(동일 y범위 48~732)인데 "라인 스트립 평균 y"로 계산 → row3~8 중심이 전부 ~407px로 수렴 → 행 라벨 6장이 **같은 위치에 겹침** |
| **행 9~21 화면 밖 소실** | 1940~1945 | L1 top 위로 38px씩 투영(y=27부터 음수) → 캔버스 밖 클립 |
| 행 해석 충돌 | 1915 주석 "row 2=통로" vs coordOf 결과 | 통로 행(Y=2)은 계산되나(1923~1931) 슬롯들이 Y=2/3으로 뭉치고 상단만 Y=9로 튐 |

**결론**: "X 9열·Y 21행·통로 번호"는 **코드 주석의 설계 사양일 뿐 실제 렌더/매핑은 그 범위를 채우지 못함**. 통로 좌표(특히 X=2·5·8)가 완전 결여된 것이 ①의 핵심.

## 3. 문제 ② — 배치도 표시 좌표값 혼선

### 요구사항 (현장)
화면에 표시되는 좌표값이 어디서든(검색·총괄·엑셀·이동 명령) **같아야** 함.

### 실측: 좌표 체계 2~3중 분열
| 경로 | 좌표계 | 예 (A-L1 슬롯5) |
|---|---|---|
| A동 단일 화면 (gridLabels.coordOf) | 신규 논리좌표 X=1~9(라인+통로)/Y=1~21 | `9-2` |
| 총괄 미니맵·검색 (coordOfAll) | 구 computeGridCoords 픽셀 클러스터링 | `11-5` |
| 엑셀 export (3682~3690) | 자체 구 클러스터링 + rowLabelOf 복붙 | 상이 |
| 좌표입력 이동 (moveSelectedToCoord 2736~2746) | 구 좌표계 해석(1~6열) | 9열 입력 시 "범위 밖" 거부 |

- 행 라벨 규칙이 **3벌 중복 구현**(2066 gridLabels / 2736 좌표이동 / 3682 엑셀) — 현재 복붙 수준 동일이나 **한 곳만 수정하면 조용히 분열** (OpenClaw B-2, 스팟검증 통과)
- 화면 툴팁(3924)은 신좌표 `9-2`, 검색(4631)·엑셀(3710)은 구좌표 — **렌더 파이프라인 자체가 서로 다른 맵 사용** (OpenClaw B-4)
- `coordToZoneAll`(2081)은 중복 좌표 시 **첫 존만 기록**(`if (!m.has(coord))`) — 동일 좌표 칸은 검색 도달 불가 + "충돌 0건" 판정이 중복을 은폐했을 가능성 (OpenClaw B-1)

**결론**: 22fd6f2의 "열-행 통일"은 문자열 순서만 통일 — **값 체계(좌표 계산 원리)는 경로별로 분열**. ②의 본질.

## 4. 문제 ③ — 위치 이동 시 고정 로케이션 값 동반 이동 (신규 심층 조사)

### 규칙 (CLAUDE.md 8/31)
"위치번호는 칸 데이터 수기 지정값 — **번호는 칸 소유, 제품 이동해도 불변**"

### 조사 결과 — 3갈래로 분해
| 갈래 | 실측 동작 | 판정 |
|---|---|---|
| (a) 제품(pn) 이동 | data(PlacementMap)만 수정, zone 객체 불변 → **locNo는 원칸에 유지** (드래그 2218~2452, 체인시프트 2397~2411, 수기편집 3197~3209 등 setLayoutState 호출 0곳) | ✅ 규칙 준수 (정상) |
| (b) 칸/셀 이동 | zone.style만 이동 — id·제품·**locNo가 한 덩어리로 새 좌표로 이동** (moveSlotTo 2636~2660, moveCellTo 2663~2691, 방향키 3901~3909, moveSelectedToCoord 2719~2777, groupMove 2458~2514, swapLines 2973~3005) | ⚠️ 칸 소유론 정상(주석 2456~2457 명시)이나, **좌표 라벨은 그리드 고정·번호만 칸을 따라가** 사용자가 "고정값이 같이 이동한다"고 인식하는 경로 |
| (c) **다품목 칸 locNos 비동기화** | **실버그**: locNos[i]는 데이터 items[i]와 짝짓는 규약(95~96행)인데, 제품 입출·체인시프트·칸 내 재정렬 시 **locNos 배열을 함께 시프트하는 코드가 없음** → 제품이 빠지면 남은 제품이 앞 번호를 물려받고, 나간 제품의 번호가 칸에 남아 다른 제품에 붙음 (예: A-L5-6 locNos[114,115,116] 3품목 → 1개 이탈 시 남은 2개가 114·115 표시) | ❌ **규칙 위반 실버그 (HIGH)** |

- locNo/locNos 기록 지점은 빌드 2곳뿐(469~470 정적 맵, 503 L7 하드코딩) — 이동 중 재계산·재부여 코드 **0곳**
- zone.id(존ID 문자열)는 전 경로 **불변** → "존ID가 이동을 따라간다"는 해석은 성립 안 함
- 마스터 location 문자열은 동기화 제거(8/31)로 **이동과 무관하게 옛값 잔류** → 반대 방향 혼동(제품을 옮겨도 화면의 '로케이션' 표시는 그대로) 유발
- 스냅샷 저장/복원은 zone 통째 왕복 → 이동 결과 그대로 유지되나, **L7은 이중 번호 체계**(빌드 115+i vs A_LOCNO_MAP 136~151)로 소스에 따라 표시가 갈릴 수 있음

**결론**: ③의 실체는 (c) **다품목 칸 locNos↔제품순서 동기화 누락**이 유일한 데이터 버그이고, (b) 칸 이동 시 번호 동반은 코드 의도(칸 소유)이나 **"번호는 물리 좌표에 귀속"이어야 한다는 현장 인식과 충돌** — 어느 쪽이 맞는지 규칙 재확인 필요. (수정 우선순위: ①(c) locNos 동기화 → ②(b) 사용자 의도 재확인 → ③L7 이중 체계 정리)

## 5. 좌표 소실·겹침 — 직접 원인 요약 (v1 재확인)

1. **B/C/D동 좌표 라벨·툴팁 전멸**: 미커밋 gridLabels(1889~2013)가 A동 전용 하드코딩(getColCenterX/getRowCenterY의 A-L 필터)이고 동 게이트 없음 → B/C/D는 모든 후보 0 → 라벨 전량 `continue`, coordOf 빈 맵. HEAD는 computeGridCoords 공통 경로(정상) — **diff에서 삭제됨**
2. **coordOf 슬롯 구분 불가**: 밴드 최근접 매칭(1976~2013)이라 한 라인 내 슬롯 구분 실패 → 인접 슬롯 동일 좌표 공유·튐 (L3-17이 6-9로 표시되는 류) — "좌표로 칸 지정" 규칙 붕괴
3. **B/C/D 위치번호 전멸**: 자동부여(computeDongLocMap 등) 삭제 후 저장값(storedLocNos)만 읽는데 B/C/D 존은 빌더가 locNo를 부여한 적 없음 → 전멸. 수기값 공급원 미연결
4. **A동 번호 이중 렌더**: gridLabels의 locOuter/내부 라벨(2015~2048) + ZoneCell 기존 측면 locNo(6426~6439) 동시 표시
