# 작업지시서 — 로케이션 수동 입력 시 기본 배정 번호 표시 (opencode)

> **지시자**: Hermes (2026-09-05) · **실행자**: opencode · **검증자**: Hermes (재실측)
> **성격**: 8c7c25a/fd2d629(수동 입력) 후속 개선 — **편집(수정)할 때 그 칸의 기본 자동 번호를 보여줘서**, 사용자가 "그 번호 그대로 쓸지/다른 번호로 바꿀지" 판단하게 한다.

---

## 1. 문제 (사용자 증언)

- A동 수정 모드 → 칸 클릭 → 인라인 편집이 열리면, **로케이션 input이 빈 상태**(placeholder "로케이션 첫 번호")만 보인다.
- 사용자는 이 칸에 **기본으로 배정된 로케이션 번호가 몇 번인지 모른다** → "그대로 쓸지, 다른 번호로 바꿀지" 결정 불가.

## 2. 요구 (사용자)

1. **수정(편집)할 때** 그 품목(칸)에 기본 배정된 로케이션 번호가 **보이게** 한다.
2. 그래서 사용자가 "기본 번호 그대로 쓸 건지, 다른 번호로 할 건지" 확인 가능.

## 3. 현재 코드 (반드시 읽고)

- `product-display.tsx`
  - ZoneCell에 이미 `locNos` prop 전달 (5199행 `locNos={coordNosByZone.get(z.id)}`, 6050 주석, 6517/6536 타입) — **기본 자동 번호 배열**.
  - 로케이션 input: 6610-6627행 `value={editLocValue}` `placeholder="로케이션 첫 번호"`.
  - 편집 state: `editLocVal` (부모 1440행), `handleCellClick`이 편집 열 때 `setEditLocVal(manualLocNos[zid] ?? "")` (3330행).
  - manual 값 = `manualLocNos[zid]`. 기본 자동 번호 = `locNos` prop(또는 dynLocNos.byZone).

## 4. 구현 방안 (권장 — 가장 단순·명확)

**편집 중 로케이션 input의 placeholder를 "그 칸의 기본 자동 번호"로** 표시하거나, **input 위/옆에 작은 라벨로 "기본: N"** 표시. 두 방식 중 코드 구조상 자연스러운 것으로.

구체적으로:
1. ZoneCell이 `locNos` prop을 이미 받으므로, 로케이션 input 렌더 시:
   - **placeholder**: `로케이션 (기본: {locNos[0]})` 형태 — 첫 번호 표시. 다품목이면 `기본: {first}~{last}` 또는 `기본: {first} 외 N개`.
   - 또는 input 아래/옆 회색 미니 라벨 `<span>기본 배정: {locNos.join('~')}</span>`.
2. **빈 값(자동 모드) = 기본 번호 유지** 의미임을 명확히: placeholder가 "기본 N번"을 보여주므로, 사용자가 input을 비우고 저장하면 N번(자동)이 그대로 적용된다는 게 시각적으로 전달된다.
3. manual 값이 이미 있는 칸은: input value에 manual 값이 채워져 표시(기존 동작), placeholder 대신 value로 보임.
4. A동 전용 (isA 조건) — B~E는 추후.

화면 실측 (A동 수정 모드):
1. manual 없는 칸 편집 → 로케이션 input에 **기본 번호가 보인다** (placeholder 또는 라벨). 예: A-L4-12 기본 60.
2. 그 input을 비우고 저장 → 기존 자동 번호 유지(회귀 없음).
3. 새 값 입력 → manual로 바뀜(기존 동작 유지).
4. manual 있는 칸은 채워진 값 표시(회귀 없음).
