# 작업지시: 제품배치도 검색 결과 정렬 — 정확 일치 우선 (2026-08-19)

① 역할: React + TypeScript 프론트엔드 로직 전문가. 제품배치도 페이지의 검색 결과 정렬을 수정한다.

② 상황:
- 프로젝트: VF-new. 작업 대상 파일 **1개만**: `frontend/client/src/pages/product-display.tsx`
- ⛔ 그 외 어떤 파일도 수정/생성 금지 (docs/, backend/, product-display-utils.ts, a-data.ts 등 전부 금지)
- 기존 구현 (건드리지 말 것):
  - `searchResults` useMemo (1036~1079줄): 검색어 → Hit 배열. 배치(data 순회) + 미배치(unplaced) 통합. **여기가 수정 대상**
  - `gotoSearchHit` (1081~1098줄): 결과 클릭 시 동 이동/깜박임/미배치 탭 이동 — **수정 금지**
  - 검색 UI 렌더링 (2186~2228줄): 검색창 + 결과 목록, `위치 {dong}동 {zone}` / `미배치 · 로케이션 {loc}` 표시 — **수정 금지**
  - 시프트 로직(applyPlacementEdit/aSeq/aZonesOf), 인라인 편집, 배정 다이얼로그 — **수정 금지**
- Hit 타입 (1039~1046줄): `{ pnum, name, loc, zone, dong, placed }`

③ 문제 (사용자 실측):
- 검색창에 "28"을 입력하면 **정확히 28번 제품이 결과 맨 위(첫 번째)에 나와야 하는데**, 현재는 순서 없이 data 순회 순서대로 나와서 28이 결과 목록에서 안 보이거나 뒤로 밀림.
- 원인: `searchResults`가 `hits.slice(0, 40)`으로 잘라내기만 하고 **정렬이 없음**. data 순회가 A-L1-1부터 시작해 "28"은 40개 제한 밖으로 밀려날 수 있음.

④ 결과물 (완료 조건):
`searchResults` useMemo에서 `hits`를 아래 **정렬 규칙**으로 정렬한 뒤 `slice(0, 40)`:
1. **정확 일치 (우선순위 0)**: `h.pnum === q` (검색어와 제품번호가 완전히 같음) — 맨 위
2. **번호 접두 일치 (우선순위 1)**: `h.pnum.startsWith(q)` (예: "28" → 28, 280, 285)
3. **그 외 (우선순위 2)**: 제품명/로케이션/바코드 부분 일치 (현재 filter에 걸린 나머지)
- 같은 우선순위 안에서는 **배치된 제품(placed)이 미배치보다 먼저**, 그다음 pnum 오름차순(숫자 순) — 단, pnum이 문자열이므로 `parseInt` 비교 후 같으면 문자열 비교.
- 검색어가 숫자로만 이루어진 경우(예: "28")에 특히 정확 일치가 맨 위로 오도록.
- 구현 팁: filter 후 각 Hit에 `rank` 필드(0/1/2)를 붙이거나, 정렬 comparator에서 직접 계산. Hit 타입 변경 없이 comparator 안에서 계산하는 방식을 권장(타입 확장 최소화).

⑤ 기준:
- 기존 필터 조건(pnum/name/lgmd/barcode/loc — 실제 코드는 pnum/name/loc/barcode)은 그대로 유지 — **정렬만 추가**.
- `slice(0, 40)` 유지.
- 기존 UI/동작 변경 금지.
- TypeScript 검증: `cd frontend/client && npx tsc --noEmit` → **수정 파일에서 새 에러 0건** (프로젝트 전체 기존 에러와 무관).
- 자체 리뷰 (필수): 아래 케이스로 정렬이 의도대로 되는지 시뮬레이션하고 결과를 보고에 포함:
  - S1: "28" 검색 → 정확 일치 "28"이 **첫 번째**, 그 뒤 280/285 등 접두 일치, 그 뒤 이름/기타
  - S2: "2" 검색 → "2"(정확) → 20, 200, 201... (접두) → 이름에 "2" 포함
  - S3: "모던" 검색 → 이름 매칭만 (숫자 정확 일치 없음) — 기존 순서대로 정상 동작
  - S4: 배치 28이 미배치 28보다 먼저 (동일 pnum 중복 방지 seen 로직 유지 확인)
- 수정 후 **변경 코드 요약 + 리뷰 결과 표 + tsc 결과**만 출력. 코드 전문 출력 금지.
- 커밋/푸시 금지 (Hermes가 처리).
