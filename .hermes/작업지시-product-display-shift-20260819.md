# 작업지시: A동 제품배치도 시프트 로직 버그 수정 + 로직 리뷰 (2026-08-19)

① 역할: React + TypeScript 프론트엔드 로직 전문가. A동 배치 시프트(밀림) 로직의 버그를 수정하고, 수정 후 시나리오 검증(자체 리뷰)까지 수행한다.

② 상황:
- 프로젝트: VF-new (Django + React/Vite). 프론트: `frontend/client`
- 작업 대상 파일 2개만:
  1. `frontend/client/src/pages/product-display.tsx` (3120줄, A동 배치도 페이지)
  2. `frontend/client/src/pages/product-display-utils.ts` (151줄, 시프트 유틸 — 수정 필요 시에만)
- ⛔ 그 외 어떤 파일도 수정/생성 금지 (docs, backend, 기타 pages 파일 전부 금지)
- 기존 구현 위치(건드리지 말 것):
  - `buildADongLayout` (142~290줄) — 레이아웃 생성. **수정 금지**
  - `DONG_LAYOUTS` (630~671줄) — **수정 금지**
  - `loadPlacement`/`defaultAPlacement`/`saveData`/`resetData`/`exportJSON` — **수정 금지**
  - 인라인 편집 UI(handleCellClick 1546~1552, commitInlineEdit 1632~1660), confirmAssign(1724~1750)의 **호출부는 유지**, 내부에서 applyPlacementEdit로 넘기는 인자는 그대로 둔다.
- 관련 함수(이해용):
  - `aSeq` (1079~1081): `DONG_LAYOUTS` A동 zones의 id 목록 — **이 순서가 핵심 버그 원인**
  - `zoneOrderA` (1555~1568): A동 물리 순서 comparator (L1-1→L1-19→L2-1→…→L6-19→L7-{col}-{row}→X1→X2, 나머지 뒤)
  - `aZonesOf` (1571~1577): 시프트에 쓰는 A동 zone 순서 배열
  - `applyPlacementEdit` (1580~1629): 칸 편집 공통 (중복 제거 + A동 한 칸씩 당김)
  - `aShiftInsert` (product-display-utils.ts 30~78): 드래그앤드롭 insert 이동 (seq를 물리 순서로 가정)
  - `groupShiftInsert` (product-display-utils.ts 110~151): 그룹 이동 (같은 seq 사용)

③ 문제 (사용자 실측 증상 2건):
1. **"A동 1-16이 빈칸으로 남고 뒤로 밀리지 않는다"** — 칸 값을 비웠을 때 뒤 칸들이 앞으로 당겨지지 않음.
   원인: `applyPlacementEdit` 1612줄 `if (dupZones.size === 0) return next;` — 중복이 없으면(칸 비우기 포함) 시프트가 아예 실행되지 않음.
2. **"제품 1번(1-1)이 2-18로 이동했다"** — 시프트가 물리 순서와 다른 순서로 동작해 엉뚱한 칸이 밀림.
   원인: `aSeq`가 `buildADongLayout`의 **빌드 순서**(line 내림차순: L6-1~L6-19, L5-1~…, L2-1~…, L1-1~L1-19, L7…, X1, X2) 그대로라, "물리 순서" 주석과 불일치. 시프트가 L1→L2→…→L6이 아니라 L6→L5→…→L1 방향으로 계산됨. 예: 2-18에 "1" 입력 시 1-1의 "1"이 중복 제거되고, 시프트 구간이 L1-19 다음을 L7-1-1로 잘못 이어붙임.

④ 결과물 (완료 조건 — 아래가 모두 되면 완성):
1. **aSeq를 물리 순서로 정렬** — `aSeq` useMemo(1079~1081)가 zoneOrderA와 동일한 순서(L1-1→L1-19→L2-1→…→L6-19→L7-1-1→L7-1-2→…→L7-8-2→X1→X2, A-NEW 등은 뒤)를 반환하도록 수정.
   - 주의: `zoneOrderA`가 1555줄(useMemo보다 아래)이라 useMemo 안에서 직접 참조 불가. **파일 상단(1079 이전)에 동일한 정렬 comparator를 별도 const로 정의**하고 aSeq에서 사용. 기존 zoneOrderA(1555)는 제거하지 말고 유지(중복 정의 방지를 위해 상단 comparator를 사용하도록 바꿔도 됨 — 단 aZonesOf의 extra 정렬 동작이 달라지면 안 됨).
   - 정렬 비교 규칙 (기존 zoneOrderA와 동일해야 함):
     - `A-L(\d+)-(\d+)-(\d+)` (L7): [0, line, col*2 + (row-1)] — A-L7-1-1=[0,7,0], A-L7-1-2=[0,7,1], A-L7-2-1=[0,7,2], …
     - `A-L(\d+)-(\d+)` (L1~L6): [0, line, cell]
     - `A-X1`=[1,0,0], `A-X2`=[1,1,0]
     - 그 외 = [2,0,0]
     - 비교: t1-t2 || l1-l2 || n1-n2
2. **applyPlacementEdit에 "빈칸 메우기 시프트" 추가**:
   - 편집 후 **물리 순서상 값이 삭제된(빈칸이 된) 칸이 하나라도 있으면**, 그 빈칸부터 뒤 A동 칸들을 한 칸씩 앞으로 당기고, 당김 구간의 맨 끝 칸을 비운다. (맨 끝 칸 빈칸 = 항상 배치의 마지막에만 빈칸 존재)
   - 중복 제거 시프트(기존 규칙)와 통합: 가장 앞쪽(물리 순서 기준)의 빈칸 또는 중복 제거 칸부터 단일 패스로 당김.
   - **편집 칸 zid의 입력값은 시프트로 덮어쓰지 않는다** (zid 직전까지만 당기고 zid는 보존). 단, zid 자체가 중복 제거로 비워진 칸이면 그 칸이 당김 시작점이 된다.
   - 다품목 보존 칸(restKept) 기존 처리 유지 — 남은 품목이 있는 칸은 당김 구간에서 제외되는 현재 로직 보존 (단, 물리 순서 정렬 후에도 동작하도록).
   - **B/C/D동은 절대 건드리지 않음** (A- 접두사만).
3. **product-display-utils.ts의 aShiftInsert/groupShiftInsert에 전달되는 seq가 물리 순서가 되도록** — 1번에서 aSeq 자체를 정렬하면 자동 해결. utils 파일 수정이 필요 없으면 수정하지 말 것.
4. **자체 로직 리뷰 (필수)** — 수정 후 아래 시나리오를 **직접 시뮬레이션(머리 또는 임시 스크립트)해서** 각 케이스의 기대 결과와 실제 결과가 일치하는지 확인하고, 보고에 표로 포함:
   - C1: 1-16 비우기 → 1-16에 1-17의 값이 들어오고, 1-17~… 전부 한 칸씩 당겨지며, **맨 끝 칸(X2 또는 마지막 A zone)이 빈칸**. L7/X에 엉뚱한 값 이동 없음.
   - C2: 2-18에 "1" 입력 (제품 1이 1-1에 있음) → 1-1에서 "1" 제거(빈칸), 1-1~2-17 한 칸씩 앞으로 당김, 2-17 빈칸, 2-18="1" 유지. **1-19에 L7 값이 들어오는 현상 금지**.
   - C3: 1-1에 "5" 입력 (제품 5가 2-18에 있음) → 2-18에서 "5" 제거, 2-18~끝 한 칸씩 당김, 맨 끝 빈칸, 1-1="5" 유지.
   - C4: "19,28" 다품목 입력 (19가 1-15, 28이 2-19에 있음) → 두 중복 칸 제거, 물리 순서상 가장 앞쪽(1-15)부터 당김. 다품목 보존 규칙 확인.
   - C5: 빈칸이 이미 2개 이상 존재하는 상태에서 편집 → 가장 앞쪽 빈칸부터 당기고 나머지 빈칸도 순서대로 메워져 **맨 끝 이후만 빈칸**이 되거나, 기존 규칙(가장 앞쪽부터)대로 안전하게 처리됨을 확인.
   - C6: 1-16 비우기 → 2-18에 "1" 입력 연속 2회 조작 → 최종 상태가 물리 순서 기준으로 올바른지 (중간 빈칸 없음, 제품 1이 2-18, 맨 끝만 빈칸).
   - C7 (회귀): 기존 중복 시프트 규칙 케이스 — 1-19에 "33" 추가(33이 1-16에 있음) → 1-16에서 33 제거 후 1-16~1-18 당김, 1-19="33", 맨 끝 빈칸.
