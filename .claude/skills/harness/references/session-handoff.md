# 세션 핸드오프 (Session Hand-off & Fork)

> 출처: Harness Engineering 자료 (실밸개발자, 2026-06-30)
> 위치: `harness/SKILL.md` 컨텍스트 관리의 상세 참조 문서

## 컨텍스트 임계치 (필수)

| 사용량 | 상태 | 액션 |
|--------|------|------|
| **< 20%** | 쾌적 | 일반 작업 계속 |
| **20~30%** | 양호 | 작업 마무리 준비 |
| **30~40%** | ⚠️ 주의 | **새 세션 시작 또는 핸드오프** 고려 |
| **40~50%** | 🚨 위험 | 즉시 핸드오프 / Fork 실행 |
| **50%+** | ❌ 불가 | 현재 작업물 **전부 폐기**. 새 세션에서 처음부터 |

> 출처 인용: *"50% 넘어가면 퀄리티가 안 좋은 코드를 쓰고 ... 전부 쓸모 없다라고 생각해야 돼요"*

## Fork vs Hand-off

### 🔀 Fork (포크)
- **방식**: UI의 "이 지점에서 새 채팅" 버튼으로 세션 복제
- **컨텍스트**: 선택한 분기점까지의 대화 **자동 상속**
- **장점**: 요약 작성 불필요, 과거 맥락 그대로 유지
- **단점**: 누적된 컨텍스트가 같이 따라옴 (퍼센티지가 분기점 시점으로 리셋만 됨, 0은 아님)
- **사용 시점**: 코드가 완벽하게 작동했던 마지막 시점 직후, 새로운 작업으로 넘어가기 전

### 📋 Hand-off (핸드오프)
- **방식**: 기존 세션 종료 → 새 세션에 요약본(인수인계서) 수동 주입
- **컨텍스트**: 4요소 요약본만 전달 (대화 전체 ❌)
- **장점**: 깨끗한 0% 컨텍스트, 정제된 핵심만 전달
- **단점**: 요약 작성 시간 소요, 정보 손실 가능
- **사용 시점**: 에러 수정으로 대화가 너무 길어졌거나, 완전히 다른 작업으로 전환

## 핸드오프 절차 (4단계)

### Step 1. 기존 세션에서 요약본(인수인계서) 추출

컨텍스트가 **30~40% 도달 시점**에 다음 프롬프트 입력:

```
대화창 컨텍스트 용량이 꽉 차서 새로운 세션으로 이동해 작업을 이어가려고 해.
새 세션의 AI가 현재 맥락을 완벽히 이해하고 즉시 작업을 재개할 수 있도록,
다음 4가지 항목을 포함한 상세한 인수인계서(요약본)를 작성해 줘.

1. 현재까지 완료된 작업 진행 상황 및 핵심 구현 로직
2. 지금까지 수정하거나 새로 생성한 파일 목록과 주요 변경 사항
3. 현재 직면해 있는 에러, 버그 또는 미해결 문제점
4. 다음 세션에서 당장 이어서 실행해야 할 최우선 목표와 권장 접근 방식
```

### Step 2. 새 세션 생성

기존 세션을 닫고(필요시 보존) 완전히 새로운 대화창을 엶.

### Step 3. 새 세션에 요약본 주입 + 작업 지시

새 세션의 첫 프롬프트:

```
이전 세션에서 진행하던 작업을 이어서 할 거야.
아래 전달하는 인수인계서를 읽고 맥락을 파악한 뒤,
명시된 '다음 세션 최우선 목표'를 곧바로 실행해 줘.

[복사한 인수인계서 내용 붙여넣기]
```

### Step 4. 검증

새 세션에서 첫 작업 후 `qa` 에이전트로 컨텍스트 정확성 검증.

## 포크(Fork) 절차

1. **분기점 선택**: 대화창에서 컨텍스트가 엉키기 전, **코드가 완벽하게 작동했던 마지막 메시지**로 스크롤
2. **Fork 버튼 클릭**: 메시지 하단의 메뉴(점 세 개 / 갈래 화살표 / "이 지점에서 새 채팅") 클릭
3. **새 세션에서 재개**: 선택한 분기점까지의 컨텍스트가 자동 상속됨

### 분기점 선택 기준 (우선순위)

| 우선순위 | 기준 |
|---------|------|
| 1순위 | 컨텍스트가 30~40% 넘기기 직전의 메시지 |
| 2순위 | 코드가 완벽하게 작동했던 마지막 지점 (테스트 통과 직후) |
| 3순위 | 하나의 큰 작업을 마치고 다음 단계로 넘어가기 직전 |

## 절대 금지

- ❌ **`/clear` 또는 `/compact` 명령어 사용**: 강연자가 강력히 반대. 컨텍스트가 강제 비워지면 중요한 규칙/상태도 같이 사라짐
- ❌ **컨텍스트 50%+ 에서 작업 계속**: 결과물 신뢰 불가, 전부 폐기 대상
- ❌ **요약 없이 새 세션 시작**: 새 세션은 맥락을 모르므로 첫 작업부터 망함

## 핸드오프 vs 포크 선택 기준

| 상황 | 선택 |
|------|------|
| 안정 시점에서 새 작업 시작 | **Fork** |
| 에러 수정으로 대화가 꼬여서 정리 필요 | **Hand-off** |
| 다른 프로젝트/기능으로 전환 | **Hand-off** |
| 같은 작업 흐름 안에서 다음 단계 진행 | **Fork** |
| 컨텍스트가 이미 40% 넘었고 작업이 단순 | **Hand-off** |
| 컨텍스트가 이미 40% 넘었고 작업이 복잡 | **둘 다 위험. 작업 중단하고 재계획** |
