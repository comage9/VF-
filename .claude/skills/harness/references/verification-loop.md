# 검증 루프 (Verification Loop)

> 출처: Harness Engineering 자료 (실밸개발자, 2026-06-30)
> 위치: `harness/SKILL.md` 6축 중 ⑤ 검증의 상세 참조 문서

## 검증 3가지 방법

| 방법 | 설명 | VF-new 적용 |
|------|------|------------|
| **① 셀프 검증 루프** | AI가 작업 후 스스로 결과물을 재확인 | 작업 완료 후 AI가 checklist 기반 자가 점검 (qa 스킬 사용) |
| **② 자동 테스트 실행** | AI에게 "테스트를 돌려라"고 명확히 지시, 결과 직접 확인 | `pytest`, `npm test`, Django `manage.py test` 자동 실행 후 결과 보고 |
| **③ 다른 에이전트 교차 리뷰** | 작업한 AI가 아닌 다른 에이전트가 객관적 리뷰 | `qa` 에이전트가 `frontend-dev`/`backend-dev` 작업물 리뷰 |

## 셀프 검증 루프 자동화 4요소

> 출처의 강연자가 LangChain 벤치마크 사례(+14% 성능)에서 강조한 핵심 4가지

### 1. 결과 재확인 및 자동 컨텍스트 수집
- 단순히 "다시 확인해"가 아니라, **검증에 필요한 컨텍스트를 자동으로 모아주는 루프**
- AI가 자기 결과를 재평가할 때 필요한 주변 정보(스키마, 컨벤션, 최근 변경 이력)를 자동 첨부
- VF-new 적용: `qa` 에이전트가 review 시 CLAUDE.md + 최근 commit diff 자동 첨부

### 2. 진행 불가(막힘) 상태 탐지
- 검증 과정에서 AI가 오류를 해결 못 하고 **정체**되거나 **엉뚱한 방향**으로 흐르는 것을 자동 감지
- 감지 신호: 같은 에러 3회 반복 / 토큰만 소모하고 진행 없음 / 컨텍스트 윈도우 소진
- VF-new 적용: `qa` 에이전트가 "막힘" 판단 시 → 사용자에게 에스컬레이션, 컨텍스트 재설계 요청

### 3. 테스트 및 교차 리뷰 환경 연동
- AI가 작업을 끝냈을 때 "어떻게 확인할지"를 명확히 안내
- **테스트 자동 실행** + **다른 에이전트 교차 리뷰** 둘 다 하네스 안에 장치
- VF-new 적용: 작업 완료 후 자동 트리거:
  1. backend 작업 → `python manage.py test` 자동 실행
  2. frontend 작업 → `npm run build` 통과 확인
  3. `qa` 에이전트가 양쪽 결과 교차 검증

### 4. 반복되는 실수의 규칙화 (피드백 루프)
- 자동화 검증에서 **같은 실수가 반복**되면 → '개선' 단계에서 **새 규칙**으로 추가
- 다음 작업의 '맥락'으로 제공 → 하네스가 점진적으로 똑똑해짐
- VF-new 적용 위치:
  - 같은 실수 2회 반복 → CLAUDE.md "⚠️ 중요 규칙" 섹션에 추가 검토
  - 같은 실수 3회 반복 → 절대 위반 금지 규칙으로 승격

## 6축 중 검증 위치

```
① 구조 → ② 맥락 → ③ 계획 → ④ 실행 → ⑤ 검증 (← 여기) → ⑥ 개선
                                              ↑
                                  [셀프/자동/교차] 검증
                                              ↓
                                실패 시 → ② 맥락 또는 ⑥ 개선으로 피드백
```

## 실패 처리 워크플로우

```
[실행] → [검증]
          ├─ 통과 → 다음 작업 또는 종료
          └─ 실패 → 원인이 '실행'인지 '맥락'인지 판단
                      ├─ 실행 문제 → 재실행 (다른 접근법)
                      └─ 맥락 부족 → ② 맥락 단계로 회귀 (CLAUDE.md/references 보강)
                                   → 같은 실수 반복 시 ⑥ 개선으로 영구 규칙화
```
