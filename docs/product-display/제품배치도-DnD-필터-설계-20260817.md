# 제품배치도 — 드래그앤드롭 재배치 + 분류·단수 필터 설계서 (최종)

작성: 2026-08-17 · 상태: 에이전트 협의 완료, 구현 대기
협의: 3 에이전트 병렬 (DnD 로직 / 데이터 일관성 / 필터·단수) — 의견 반영 완료

## 1. 요구사항
1. 셀 제품번호를 **드래그앤드롭**으로 이동 → 이동품목이 새 위치에 들어가고, 원래 있던 품목들은 **한 칸씩 뒤로 밀림** (insert)
2. **분류 필터** (동+분류 선택 → 해당 품목 필터링) → 필터된 품목 드래그 재배치
3. **단수 표시/선택** (모던플러스 → 5단·6단·4단·3단 → 해당 단수만 필터 → 위/아래 이동)

## 3. 최종 설계

### 3.1 드래그앤드롭 — dnd-kit core (기존 설치, production-plan.tsx 패턴 재사용)
- **셀**: `<button draggable>` 대신 dnd-kit `useDraggable` (data 값 있는 칸). 클릭-모달과 구분: PointerSensor `activationConstraint: { distance: 5 }` — 5px 이상 드래그 시 DnD, 미만 클릭 = 기존 openAssign 모달
- **소스**: (zoneId, itemIdx) 쌍 + 이동 품목 pnum 저장 (중복 pnum 대비)
- **대상**: useDroppable — 빈 칸 포함 모든 칸. 드롭 시 insert
- **insert 규칙** (사용자 정의 반영):
  1. 소스 zone에서 품목 제거
  2. 대상 zone부터 시퀀스 끝까지 한 칸씩 shift: `next[order[i]] = old[order[i-1]]` (i = 대상+1 … 끝)
  3. 대상 zone에 이동 품목 삽입
  4. **끝에서 밀려난 품목 = 소스 빈칸으로 이동 (원형)** — 데이터 100% 보존 (132칸 고정 Record)
  - 예: [z1:210, z2:214, z3:203, z4:225]에서 210(z1)→z3 = [z1:225, z2:214, z3:210, z4:203]
  - ※ 사용자 예시(z1:빈, z5:225)는 5번째 칸이 있는 가상 시나리오 — 실제 132칸 고정이므로 끝 품목은 소스로 순환. 필요 시 '미배치로 이동' 옵션도 가능
- **다품목 칸(B/C/D)**: 칸 내부 품목 순서도 드래그 재정렬 (같은 zone 내 itemIdx 이동), 칸 간 이동은 1품목 단위 insert
- **가드**: 소스=대상 무시 · 빈 소스 무시 · 드래그 중 대상 하이라이트(ring emerald + scale, 기존 amber/blue와 구분)

### 3.2 분류·단수 필터
- **필터 바** (동 탭 아래, E동/총괄은 숨김): `[분류 select] [단수 select] [초기화]`
  - 분류 옵션: 해당 동 배치 품목의 category_lg (A동=A_ZONE_CATEGORY_LG, B/C/D=PNUM_INFO.lg)
  - 단수 옵션: 선택 분류 내 품목의 단수 — **parseInt 오름차순 정렬** (10단<2단 문자열 문제 방지)
- **단수 파싱**: `extractDansu(name)` = `name.match(/(\d{1,2})\s*단/)` first-match, 1~99 검증, 실패 시 '' → '단수없음' 버킷. 품목→단수 **Map 1회 캐시(useMemo)**
- **필터 결과**: 조건 셀 하이라이트(ring) + 우측 패널(제품번호·이름·단수·현재 위치, 클릭 시 셀 이동=기존 gotoSearchHit 재사용)
- **필터 상태에서 드래그**: 이동 후 필터 재계산 (useMemo 자동), 대상이 필터 밖이면 대상 셀 flashZone 표시
- **상태**: filterDong/filterCat/filterDansu — **컴포넌트 state로만** (saveData는 data만 저장, 필터는 저장 안 함)

### 3.3 저장
- 기존 saveData(localStorage, rank-a-v14) 버튼 유지 + **드래그 직후 자동 localStorage 저장**
- **loadPlacement() 수정**: localStorage 값 있으면 로드, 없으면 기본값 (현재는 항상 기본값 — 버그)
- 파일 영속화는 기존 exportJSON 버튼
