## 1. 문제 현상

사용자 보고:
> "이전 클릭 시 어제 입력 사항이 보이고, 오늘 클릭 시 오늘로 돌아와야 하는데 그게 안 되고 있다."

구체적으로:
- **"이전"** 버튼을 누르면 어제 데이터가 보여야 한다 → ✅ 동작함
- **"오늘"** 버튼을 누르면 오늘(빈 화면)로 돌아와야 한다 → ❌ **어제 데이터가 그대로 남아있음**

---

## 2. 원인 분석

### 2.1 핵심 원인: 빈 응답일 때 LS_DATA 갱신 누락

`loadFromServerAndRender()` 함수의 서버 응답 처리 코드:

```javascript
// 수정 전 (버그 코드)
var serverList = (data && data.data) ? data.data : [];
if (serverList.length > 0) {        // ← 이 조건이 문제!
  LS_DATA = serverList;
}
```

**문제**: 서버에서 가져온 데이터가 **0건(빈 배열)**일 때 `LS_DATA`를 갱신하지 않습니다.
→ 이전 날짜의 데이터가 `LS_DATA`에 그대로 잔존합니다.

### 2.2 부가 원인: loadDateData 폴백 로직

`loadDateData()` 함수의 폴백:

```javascript
// 수정 전 (버그 코드)
var filtered = (LS_DATA || []).filter(function(v) {
  return !d || d === sel;     // 선택 날짜로 필터
});
// 필터 결과가 비었는데 LS_DATA가 있으면 전부 사용
if (filtered.length === 0 && LS_DATA && LS_DATA.length > 0) {
  filtered = LS_DATA.slice(); // ← 잘못된 날짜 데이터까지 전부 표시!
}
```

**문제**: 선택한 날짜에 데이터가 없으면, `LS_DATA`(이전 날짜 데이터) 전체를 표시합니다.
→ 잔존한 이전 날짜 데이터가 화면에 그대로 노출됩니다.

### 2.3 버그 발생 시나리오 (재현됨)

```
1. 오늘(7/24) 시작 → 서버 응답 0건 → LS_DATA = [] → 카드 0개 ✅
2. "이전" 클릭 → 7/23 → 서버 응답 3건 → LS_DATA = [7/23 데이터] → 카드 3개 ✅
3. "오늘" 클릭 → 7/24 → 서버 응답 0건
   → if(0 > 0) → false → LS_DATA 갱신 안 됨 → LS_DATA = [7/23 데이터] 잔존 ❌
   → loadDateData: 필터 결과 0건 → 폴백 → LS_DATA 전체 표시 → 7/23 데이터 3개 ❌
4. "다음" 클릭 → 7/25 → 서버 응답 0건 → 동일하게 7/23 데이터 잔존 ❌
```

### 2.4 헤드리스 브라우저 검증 데이터 (수정 전)

```
오늘(초기):     날짜=2026-07-24 카드=0
이전 클릭:      날짜=2026-07-23 카드=3  ← 정상
오늘 클릭:      날짜=2026-07-24 카드=3  ← ❌ 7/23 데이터 잔존
다음 클릭:      날짜=2026-07-25 카드=3  ← ❌ 여전히 7/23 데이터
```

## 3. 해결 방안 (적용 완료)

### 3.1 수정 1: LS_DATA 무조건 교체

`loadFromServerAndRender()` — 서버 응답을 선택한 날짜의 데이터로 **무조건 교체**:

```javascript
// 수정 후
var serverList = (data && data.data) ? data.data : [];
LS_DATA = serverList;                    // ← 빈 응답이어도 무조건 교체
console.info('[departure] load ls-data date=' + dateStr + ' count=' + serverList.length, ...);
```

**의도**: 선택한 날짜에 데이터가 없으면 `LS_DATA = []`로 확실히 비웁니다.
이전 날짜 데이터가 새 날짜 화면에 잔존하지 않습니다.

### 3.2 수정 2: loadDateData 폴백 제거

`loadDateData()` — 빈 결과일 때 이전 데이터를 끌어오던 폴백 제거:

```javascript
// 수정 후
var filtered = (LS_DATA || []).filter(function(v) {
  var d = (v && v.date != null) ? String(v.date).slice(0, 10) : '';
  return !d || d === sel;
});
// (제거) 필터 결과가 비었으면 LS_DATA 전체를 사용하던 폴백
renderAllWithData(filtered);             // ← 필터 결과 그대로 사용 (비어있으면 빈 화면)
```

**의도**: 선택한 날짜에 데이터가 없으면 **빈 화면이 정상 동작**입니다.
이전 날짜 데이터를 억지로 끌어오지 않습니다.

### 3.3 수정 사항 요약

| 위치 | 수정 전 | 수정 후 | 효과 |
|------|---------|---------|------|
| `loadFromServerAndRender` | `if (serverList.length > 0) LS_DATA = serverList` | `LS_DATA = serverList` (무조건) | 빈 날짜 전환 시 이전 데이터 제거 |
| `loadDateData` 폴백 | `if (filtered.length===0) filtered = LS_DATA.slice()` | 폴백 제거 | 빈 날짜는 빈 화면 표시 |

## 5. 최종 동작 흐름 (수정 후)

```
"이전"/"다음"/"오늘" 버튼 또는 datePicker 선택
  ├─ currentDate 갱신 + localStorage 영속화 (updateDateDisplay)
  └─ loadFromServerAndRender()
     ├─ GET /departure/api/ls-data?date=<선택날짜>
     │    └─ LS_DATA = serverList   (빈이면 [] 로 무조건 교체)
     ├─ GET /departure/api/vehicle-extras?date=<선택날짜>
     │    └─ mergeExtrasIntoLsData() (regions 병합)
     └─ loadDateData()
          └─ LS_DATA.filter(date === 선택날짜)   (폴백 없음)
               └─ 데이터 있으면 카드 표시 / 없으면 빈 화면
```

**핵심 원칙**: 선택한 날짜의 서버 데이터 = 화면 표시 데이터.
데이터가 없는 날짜는 빈 화면이 정상입니다.

## 6. 정리

| 항목 | 상태 |
|------|------|
| "이전" 클릭 → 어제 데이터 표시 | ✅ 정상 동작 |
| "오늘" 클릭 → 오늘로 복귀 (데이터 없으면 빈 화면) | ✅ 해결 |
| "다음" 클릭 → 미래 날짜 (빈 화면) | ✅ 정상 동작 |
| datePicker 직접 선택 → 해당 날짜 데이터 | ✅ 정상 동작 |
| 새로고침 → 선택 날짜 유지 | ✅ 정상 동작 (localStorage) |
| 날짜별 데이터 정확성 | ✅ 검증 완료 |

**결론**: "오늘" 버튼을 눌러도 어제 데이터가 남아있던 원인은,
서버에서 빈 응답(0건)이 올 때 이전 날짜의 `LS_DATA`를 갱신하지 않은 것과,
빈 결과를 이전 데이터로 채우던 폴백 로직의 조합이었습니다.
두 곳을 수정하여 날짜 전환이 정확히 동작하도록 해결했습니다.
