## 2. 기간(프리셋) · 집계 단위

### 2.1 문제 (이전)

- 기간 프리셋(`1년` 등)과 날짜 입력칸·집계(주별) 역할이 혼동됨  
- 실제 조회는 항상 `startDate`~`endDate` 기준  
- `1년`+`주별`이어도 날짜가 2주면 **2주만** 주별로 표시됨 (정상 동작이나 UX 오해)

### 2.2 개선: 프리셋 우선 + 수동 모드

| 모드 | 설명 |
|------|------|
| **preset** | 날짜를 직접 수정하지 않으면 프리셋이 기간을 결정 |
| **manual** | 날짜 칸을 직접 바꾸면 수동 기간 (프리셋 라벨 해제, 칸 강조) |

- 기본(VF): **2주일** 프리셋 + **일별** 집계  
- 기본(FC): **1년** 프리셋 + **월별** 집계  

### 2.3 프리셋 목록

| 값 | 기간 |
|----|------|
| yesterday / dayBefore | 어제 / 그제 |
| 1week / 2weeks | 1주일 / 2주일 |
| 1month / 6months | 1개월 / 6개월 |
| 1year / **2year** / **3year** | 1·2·3년 |
| **all (전체)** | 실데이터 최초 ~ 최신 출고일 |

#### 「전체」프리셋

- **시작**: `2022-02-02` (확인된 실데이터 최초일, `VF_DATA_FLOOR`)  
- **끝**: `/api/outbound/meta` 의 `latestDate` (데이터 있는 최신일)  
- 이상 연도(`0223-01-01` 등)는 메타·보간 모두에서 제외  

#### 메타 API 수정

- 파일: `backend/sales_api/views.py` → `get_outbound_meta`  
- `outbound_date >= 2022-02-02`, `year` 2022~2100 만 집계  

### 2.4 집계 단위 (일/주/월/년)

| 규칙 | 내용 |
|------|------|
| 명시 선택 | 사용자가 고른 단위를 **존중** (과거 60/180일 강제 전환 제거) |
| **6개월 이상** | **일별 선택 불가** → 자동 **주별** (약 183일) |
| 자동 모드 | ≤60일→일 · 6개월 미만 긴 기간→주 · ≤1년→주 · ≤3년→월 · 그 이상→년 |
| UI | 일별 비활성 시 `일별 불가` 안내, 도움말 툴팁 |

### 2.5 관련 상수 (프론트)

```text
VF_DATA_FLOOR = "2022-02-02"
DAY_AGG_MAX_DAYS = 183   # 6개월 이상 일별 차단
```

## 5. 실적 공백 · 예측 보정

### 5.1 조사 결과 (DB 기준, 보정 전)

주요 공백 예:

| 구간 | 일수 | 비고 |
|------|------|------|
| 2025-07-19 ~ 07-20 | 2일 | 사용자 지적 구간 |
| 2025-07-22 ~ 11-09 | 111일 | 장기간 공백 |
| 2025-11-11 ~ 12-01 | 21일 | 11/10 하루만 실적 후 공백 |

전체적으로 2022-02-02 이후 실적 앵커 사이 **약 178일** 공백(36구간).

### 5.2 DB 필드 추가

마이그레이션: `sales_api/migrations/0025_outboundrecord_is_estimated.py`

| 필드 | 타입 | 설명 |
|------|------|------|
| `is_estimated` | bool, index | True = 예측 보정 행 |
| `estimate_method` | string | 예: `trend_dow_v2` |
| `status` | 기존 필드 | 값 **`예측 보정`** |

### 5.3 1차 방식 (폐기) — `adjacent_avg`

- L∪R 품목 단순 평균, 한쪽만 있으면 풀값  
- **문제**: 일합계가 앵커보다 과도(예: 18일 522·21일 630인데 19~20일이 **736**), 장공백은 **동일 수치 반복**

### 5.4 현재 방식 — `trend_dow_v2` ✅

관리 명령:

```bash
cd backend
.\.venv\Scripts\python.exe manage.py fill_outbound_estimates
# 미리보기
.\.venv\Scripts\python.exe manage.py fill_outbound_estimates --dry-run
# 예측만 삭제
.\.venv\Scripts\python.exe manage.py fill_outbound_estimates --clear-only
```

파일: `backend/sales_api/management/commands/fill_outbound_estimates.py`

#### 알고리즘

1. **일 합계**: 앞 실적일 L ~ 뒤 실적일 R **선형 보간** (`t = 경과일/전체갭`)  
2. **요일 보정**:  
   - 전체 실적 요일별 평균 / 전체 평균  
   - 갭 전후 8주 **로컬 요일** 패턴 혼합  
   - 배율 클램프 약 0.55 ~ 1.40  
3. **품목**: 동일 `t`로 박스·매출 선형 보간 (한쪽에만 있으면 그쪽 비율만, 풀값 합산 금지)  
4. **스케일**: 품목 합 = 목표 일합계  
5. **잔차 보정**: 정수 반올림 후 목표 박스 합에 맞춤  
6. **상한**: 앵커 max × 1.12  

이상 연도·`2022-02-02` 미만 앵커 제외.

#### 재생성 결과 (검증 샘플)

| 일자 | 구분 | 박스 합 (대략) |
|------|------|----------------|

| 2025-07-19 토 | 예측 | **539** (이전 736 → 개선) |
| 2025-07-20 일 | 예측 | **627** (이전 736 → 개선) |

- 예측 행 수: 약 **46,759** (`trend_dow_v2`)  
- 빠진 일: **178일** / 구간 **36곳**

### 5.6 구글 시트 일일 동기화와의 관계

명령: `manage.py daily_outbound_sync`

| 질문 | 답 |
|------|----|
| 매일 동기화 시 과거 예측이 **통째로 삭제되나?** | **아니오** |
| 처리 방식 | 최근 **약 2일**만 `update_or_create` (전체 삭제 없음) |

- 최근 2일에 시트 실적이 들어오면, 키 불일치 시 **예측+실적 이중 행** 가능

- **권장 후속**: 동기화 시 해당 일자 예측 행 삭제 또는 `is_estimated=False`로 승격

## 12. 2026-07-13 상세 수정·보완 내역 (추가)

### 12.1 FC 입고 탭 YoY N/A 복구 및 과거 데이터 복원
* **현상**: FC 입고 탭에서 전년 동기간 대비 매출/수량 수치가 항상 `N/A`로 표시되는 현상 발생.
* **원인**: 프론트엔드 대시보드 컴포넌트(`outbound-dashboard-unified.tsx`)에서 YoY 비교 쿼리(`stats-yoy`)의 활성화 가드(`enabled`) 조건에 `dataSource === 'vf'`(출고)만 허용되어 입고 탭에서는 호출 자체가 차단되었음. 또한, 기존 DB의 과거 입고 실적(`FCInboundRecord`) 데이터 중 약 10만 건 이상의 카테고리(`category`) 필드가 빈값(`""`)으로 누락되어 집계에서 제외되었음.
* **조치**: 
  1. 호출 가드에 `dataSource === 'fc'`도 함께 포함하도록 `enabled` 조건식 수정.
  2. 카테고리가 누락된 과거 입고 데이터 **103,830건**을 제품 마스터(`MasterSpec`)와 대조하여 실제 대분류 카테고리명으로 벌크 동기화 완료.
  3. 백엔드 입고 업로드 API(`fc_inbound_upload`)에 품목명(`product_name`) 기준 카테고리 유추 로직을 추가하여 카테고리 누락을 영구 예방.

### 12.2 트렌드 그래프 클릭 시 날짜 동기화 500 에러 해결
* **현상**: 월별/주별 추이 막대 그래프 클릭 시 `Failed to fetch stats` 500 에러 팝업 발생.
* **원인**: 백엔드는 `%Y-%m-%d` (YYYY-MM-DD) 형식의 시작/종료일 파라미터만 허용하나, 월별/주별 클릭 시 YYYY-MM 형태의 불완전한 날짜 문자열이 백엔드로 전송되었음. 또한 월별 막대 클릭 시 1개월 전체가 아닌 1일 하루 대역만 설정되는 논리 오류 존재.
* **조치**: 막대 클릭 시 `groupBy` 모드(월별/주별/년별/일별)에 따라 온전한 시작일과 종료일(월 전체, 주 전체)을 계산하여 정형화된 YYYY-MM-DD 형식으로 프론트엔드에서 계산해 전송하도록 보완.

### 12.3 분류별 매출 비중 표 스크롤 기능 도입
* **현상**: 일반 카드 모드에서 상위 10개만 보이고, 10위 이하를 보려면 무조건 확대해야 하는 불편함 존재.
* **조치**: 일반 카드 모드에서도 상위 슬라이싱 제한 없이 전체 카테고리 목록을 모두 테이블에 그리도록 변경하되, 테이블 Wrapper에 `max-h-[350px]` 및 `overflow-y-auto`를 추가하여 마우스 휠로 스크롤 가능하게 개선. 스크롤 시에도 테이블 헤더가 상단에 고정(`Sticky`)되도록 UI를 세련되게 다듬음.

### 12.4 잘못된 카테고리 `'쿠팡입고'` 영구 제거 및 정합성 보구
* **현상**: 대시보드 표 상에 존재할 수 없는 임시 분류명인 `'쿠팡입고'` 대분류가 노출됨.
* **원인**: 신규 제품 등록 스크립트 실행 시 마스터 카테고리가 없는 품목들을 임시로 `'쿠팡입고'`라는 대분류로 저장했음.
* **조치**: 마스터에 `'쿠팡입고'`로 등록되어 있던 103개 품목과 관련 입고 데이터 **1,458건**의 카테고리를 분석해 원래 실체 분류명(예: `슬림서랍장` 등)이나 `'미분류'`로 일괄 갱신 및 정상화 완료. 신규 마스터 등록 시에도 출고/바코드마스터 기록에서 카테고리를 자동 유추하도록 보강.

### 12.5 제품 마스터 컬럼 밀림 해결 및 `nan` 중분류 청소
* **현상**: 제품 마스터 데스크톱 테이블에서 헤더 명칭과 본문 값의 위치가 한 칸씩 옆으로 밀려 출력됨.
* **원인**: 데스크톱 뷰 렌더링 코드에서 `로트 번호`에 해당하는 `<td>` 셀이 통째로 누락되었음.
* **조치**: `lot_number` TD 셀을 올바른 순서에 추가하여 열 정렬을 복구 완료. 또한 기존 마스터 중분류에 유입되었던 불필요한 결측 문자열 `"nan"` **980건**을 공백으로 일괄 교정 및 코지 계열 제품 오매칭 수정 완료.

### 12.6 단가 미입력 품목 일괄 복원 및 노출 조건 최적화
* **현상**: 단가가 `0원`으로 누락된 품목이 325개 존재하였고, 최신 단가와 이전 단가가 완전히 같은데도 굳이 `(이전: 00원)`이 중복 노출되어 UI가 지저분함.
* **조치**: 과거 쿠팡 입고 실적을 분석해 단가가 누락된 **66개** 품목의 단가를 자동으로 유추/주입 완료. 최신 단가와 이전 단가가 다를 때에만 `(이전: 00원)` 표시가 나타나도록 렌더링 가드 조건 추가.
