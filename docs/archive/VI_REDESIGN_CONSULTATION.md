# VF 프로젝트 UI/UX 전면 재개편 - 다중 에이전트 의견 보고서

## 📋 개요
VF(보노하우스 생산 관리 시스템)의 페이지 구성 및 UI 요소를 전면 재개편에 대한 5개 에이전트의 종합 의견입니다.

## 🔍 현재 상태 분석
- **기술 스택**: Django (Backend) + React/Vite (Frontend) + shadcn/ui + Tailwind CSS v4
- **현재 디자인**: Toss/TDS 기반 (보라색 #721FE5 강조, 카드 기반 레이아웃, 모바일 우선)
- **페이지**: /delivery, /outbound, /inventory, /production, /production-app, /master
- **디자인 문서**: DESIGN-LANGUAGE.md (2603줄)

## 👥 에이전트 1: 프론트엔드 디자인 전문가

### 핵심 의견: 카드 기반 레이아웃 유지, 모바일 최적화 강화

**기존 문제점**:
- 현재 페이지가 데스크톱 기반이어서 모바일에서 데이터가 조잡하게 표시됨
- 사이드바 너비가 모바일 화면을 압도함
- 터치 타겟 크기가 작아 실제 공장 환경에서 사용이 불편함

**개편 제안**:

### 1. 레이아웃 구조 변경
```
현재: [Sidebar 좌측 고정] + [콘텐츠 우측 스크롤]
     → 데스크톱 중심, 모바일에서 불편

제안: [상단 네비게이션 바] + [카드 그리드 콘텐츠]
     → 모바일 최우선, 탭 기반 전환
```

### 2. 페이지 구성 (모바일 우선)
- **상단**: 브랜드 로고 + 페이지 타이틀 + 최종 갱신 시간
- **탭 바**: 주요 기능 빠른 전환 (출고/재고/생산/마스터)
- **콘텐츠 영역**: 카드 그리드 (2열 모바일, 4열 데스크톱)
- **하단**: 고정 네비게이션 바 (5개 메뉴 아이콘)

### 3. 터치 최적화
- 버튼 최소 크기: 44x44px
- 카드 padding: 최소 16px
- 텍스트 크기: 최소 14px 본문
- 간격: 최소 8px 요소 간격

### 4. 색상 시스템
- 유지: #721FE5 (보라색 강조)
- 배경: #FAFAFA (연한 회색)
- 카드: #FFFFFF (흰색)
- 텍스트: 5단계 그레이 계층
- 절대 금지: 순수 검정 (#000), 넓은 면적 강조색

## 👥 에이전트 2: 백엔드 아키텍처 전문가

### 핵심 의견: API 설계 변경이 UI 개편의 전제조건

**기존 문제점**:
- Django URL이 trailing slash 없음 규칙으로 되어 있어 프론트엔드에서 혼란
- production-log 뷰가 POST만 허용하여 삭제 기능이 복잡
- 대량 데이터(240K outbound_records) 로딩 시 성능 문제

**개편 전 제안 (필수 선행 작업)**:

### 1. API 엔드포인트 정리
```typescript
// 현재: 복잡하고 일관성 없음
GET /api/production          ✅
GET /api/production/         ❌ 404
DELETE /api/production-log   ❌ 405
DELETE /api/production-log/bulk-delete  ✅

// 제안: 일관된 네이밍
GET    /api/productions              // 리스트
GET    /api/productions/:id          // 상세
POST   /api/productions              // 생성
PUT    /api/productions/:id          // 수정
DELETE /api/productions/:id          // 삭제
```

### 2. 분页 및 필터링 표준화
```json
// 모든 목록 API에 표준 파라미터
{
  "page": 1,
  "per_page": 50,
  "sort_by": "date",
  "sort_order": "desc",
  "filters": {
    "machine_number": "M001",
    "date_from": "2026-05-01",
    "date_to": "2026-05-23"
  }
}
```

### 3. 실시간 데이터 웹소켓
- 현재: 폴링 방식 (5초 간격)
- 제안: WebSocket으로 실시간 알림
- 소켓 이벤트: production_started, production_completed, inventory_low

### 4. 데이터 집계 API
```
GET /api/stats/production-summary    // 생산 요약
GET /api/stats/outbound-trends      // 출고 추이
GET /api/stats/inventory-alerts     // 재고 경고
```

## 👥 에이전트 3: UX 리서처

### 핵심 의견: 사용자 플로우 분석 기반 전면 재설계

**현재 사용자 흐름 문제**:
- 출고 현황 → 재고 확인 → 생산 계획 생성: 3단계 전환 필요
- AI 챗봇이 고정 위치에 있어 현재 페이지와 연관성 없음
- PIN 인증이 별도 페이지에서 발생하여 맥락이 끊김

**개편 제안: 태스크 기반 페이지 구조**

### 1. 메인 대시보드 (홈)
```
┌─────────────────────────────────────┐
│  VF 보노하우스    오늘 5/23 토  │
├─────────────────────────────────────┤
│  [📊 출고] [📦 재고] [🏭 생산] [🗃 마스터] │
├─────────────────────────────────────┤
│                                     │
│  ┌─────────────┐  ┌─────────────┐   │
│  │ 오늘 출고량  │  │ 재고 경고   │   │
│  │  1,234개    │  │  3개 품목   │   │
│  │ +12% ↑     │  │ 🔴 긴급     │   │
│  └─────────────┘  └─────────────┘   │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ 🤖 AI 요약                     │  │
│  │ "오늘 M001 기계 생산량 부족..." │  │
│  │ [AI 추천 보기]                 │  │
│  └───────────────────────────────┘  │
│                                     │
│  ┌─────────────┐  ┌─────────────┐   │
│  │ M001 생산   │  │ M002 생산   │   │
│  │ 진행률 67%  │  │ 진행률 45%  │   │
│  │ ████████░░  │  │ ██████░░░░  │   │
│  └─────────────┘  └─────────────┘   │
│                                     │
└─────────────────────────────────────┘
```

### 2. 태스크 중심 디테일 페이지
- **출고 관리**: 필터 → 데이터 테이블 → 내보내기
- **재고 모니터**: 경고 카드 → 품목 리스트 → 보충 발주
- **생산 계획**: 기계 선택 → 계획 생성 → AI 추천 → 실행
- **제품 마스터**: 검색 → 상세 → 편집

### 3. AI 챗봇 연동
- 현재: 고정 위치, 페이지와 무관
- 제안: 컨텍스트 인식 - 현재 페이지 기반 질문 제안
- "현재 재고가 부족한 품목은?"
- "M001 기계 오늘 생산 계획은?"

### 4. 알림 시스템
- 푸시 알림: 작업 완료, 재고 부족, 예측 대비 이상
- 인앱 알림: 최근 5건만 표시
- 알림 설정: 카톡/텔레그램 연동 옵션

## 👥 에이전트 4: 데이터 시각화 전문가

### 핵심 의견: 차트와 그래프 전면 재설계

**현재 문제점**:
- 차트가 과도한 애니메이션으로 로딩 느림
- 데이터 포인트 수가 너무 많아 다운샘플링 필요
- 색상 구분이 모호하여 정보 전달력 낮음

**개편 제안**:

### 1. 차트 타입 가이드
| 데이터 유형 | 차트 타입 | 사이즈 | 색상 |
|------------|---------|-------|------|
| 시간대별 출고량 | Area chart | 400x200 | #721FE5 점프 |
| 카테고리별 재고 | Donut chart | 128x128 | 보라 강조 + 회색 나머지 |
| 기계별 생산률 | Horizontal bar | 100% width | 진행률에 따라 보라 농도 |
| 일별 추이 | Line chart | 400x200 | #721FE5 선 + 데이터 포인트 |

### 2. 차트 규칙
- **데이터 포인트**: 최대 30개 (다운샘플링)
- **라벨**: 최대 5개만 표시
- **애니메이션**: 첫 로딩만 (transition: 300ms)
- **격자선**: 최소화 (주요 눈금만)
- **축 라벨**: 10px 이하, #7A7A7A 색상

### 3. KPI 카드 디자인
```
┌─────────────────────────┐
│ 📊 오늘 출고량          │ ← 아이콘 배지
│                         │
│ 1,234<span class="text-sm">개</span>           │ ← 36px + 18px
│                         │
│ +12.4% ↑                │ ← 트렌드
│ vs. 어제               │ ← 비교 라벨
└─────────────────────────┘
```

### 4. 진행률 표시
- 선형 프로그레스: h-4 (16px), rounded-full
- 세그먼트 바: h-6 (24px), 10개 세그먼트
- 퍼센트 표시: 숫자 + 아이콘 동시 표시

## 👥 에이전트 5: 생산 관리 도메인 전문가

### 핵심 의견: 공장 현장 사용자 요구 반영

**현재 문제점**:
- PIN 인증이 별도 페이지에서 발생하여 작업 흐름이 끊김
- 생산 계획 생성이 복잡한 폼으로 인해 현장에서 사용 어려움
- 실시간 상태 확인이 불가하여 생산 라인 지연 발생

**개편 제안**:

### 1. 기계별 작업 화면 (현장 최적화)
```
┌────────────────────────────┐
│  M001 - 1번 기계     [←]  │
│  2026-05-23 (오늘)        │
├────────────────────────────┤
│  현재 작업                  │
│  ┌──────────────────────┐  │
│  │ 토이 아이보리        │  │
│  │ T001 | Ivory        │  │
│  │ 50박스 × 10개 = 500개│  │
│  │ ████████░░ 80%      │  │
│  │ [일시정지] [완료]    │  │
│  └──────────────────────┘  │
│                            │
│  다음 작업                  │
│  ┌──────────────────────┐  │
│  │ 헬로키티 푸샤  ⏳ 대기│  │
│  │ [시작]              │  │
│  └──────────────────────┘  │
│                            │
│  [+ 추가]  [🤖 AI 추천]   │
└────────────────────────────┘
```

### 2. 실시간 상태 표시
- 작업 진행률: 실시간 업데이트
- 기계 상태: 작동 중/일시정지/오류 (색상 구분)
- 남은 작업: 카운트 다운 표시

### 3. 간편한 입력
- QR 코드 스캔으로 제품 선택
- 음성 입력으로 작업 시작/완료
- 대화형 AI: "50박스 추가해줘"

### 4. 알림 시스템 (공장 환경 최적화)
- 대형 푸시 알림: "M001 생산 완료!"
- 소리 알림: 작업 완료/오류 시
- 카톡 연동: 현장 관리자에게 자동 알림
